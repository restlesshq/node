# Restless SDK conformance kit

Everything needed to build a Restless SDK in another language and prove it
behaves like this one.

The Node SDK is the reference implementation. This directory is how that
claim is enforced rather than asserted: the test vectors are **generated by
running the Node implementation**, and the test suite fails if the
committed vectors stop matching it.

## What is here

| path | for whom | what |
|---|---|---|
| `CONTRACT.md` | everyone | The normative spec. Every requirement has a stable ID. |
| `vectors/*.json` | ports | Generated conformance cases. |
| `driver/PROTOCOL.md` | ports | The stdio interface every SDK implements. |
| `harness/run-vectors.mjs` | ports | Replays vectors through any driver. |
| `harness/fuzz.mjs` | ports | Differential fuzz against the reference. |
| `schema/v1-request.schema.json` | ports, ingest | JSON Schema for the upload payload. |
| `PORTING.md` | ports | How to port, and how to audit a port. |
| `cases.ts`, `ops.ts` | Node only | Vector inputs and the Node op table. |

A port consumes `CONTRACT.md`, `PORTING.md`, `vectors/`, `driver/PROTOCOL.md`,
`harness/` and `schema/`, pinned to a spec version. It never reads
`cases.ts` or `ops.ts`.

## Quick start (Node)

```sh
npm run spec:vectors      # regenerate vectors from src/  (writes vectors/*.json)
npm run spec:driver       # build the reference driver     (spec/driver/.build/)
npm run spec:conformance  # replay all vectors through it
npm run spec:fuzz         # self-fuzz, a smoke test of the harness itself
```

`npm test` asserts the committed vectors still match `src/`. That is the
drift guard: a behaviour change nobody intended shows up as a failing case
with a readable before and after.

## Quick start (a port)

```sh
# 1. all vectors green
node spec/harness/run-vectors.mjs --json report.json -- python -m restless._conformance

# 2. then fuzz against the reference
node spec/harness/fuzz.mjs \
  --ref  "node spec/driver/.build/node.js" \
  --test "python -m restless._conformance" \
  --iterations 20000
```

Unimplemented operations report as **skipped**, not failed, so a port under
construction gets a useful report from day one.

## Read section 2 first

`CONTRACT.md` section 2 (Shared primitives) is short, easy to skip, and the
source of essentially every silent cross-language divergence:

- Regex shorthands are not portable. `\w` and `\d` are ASCII in JavaScript,
  Go and Ruby but Unicode-aware in Python. `\s` is the reverse. Every class
  the contract depends on is enumerated explicitly.
- Three counting units appear and are not interchangeable. An emoji is 1
  code point, 2 UTF-16 code units, and 4 UTF-8 bytes.
- JSON serialization differs by language in separators, key order, number
  rendering, and non-ASCII escaping.

## Changing the contract

See `CONTRACT.md` section 16. In short: edit the requirement, regenerate
the vectors, bump the spec version, all in the same change. Changes to
masking, the redaction sentinel, fingerprints, or the wire payload also
require moving the ingest and dashboard together.
